# `mochidock-pm` 第一版 Skill 蓝图

## 定位

`mochidock-pm` 是 MochiDock 的项目管理辅助 Skill。它帮助 Codex 在探索期保持产品连续性、控制阶段范围、组织验证和交接，但不替代用户的项目经理、产品负责人和最终决策者身份。

## 典型触发语句

- “帮我整理 MochiDock 下一阶段做什么。”
- “我有几个新功能想法，帮我归类并控制范围。”
- “根据当前进度，给我一个最小可验证阶段。”
- “汇总现在完成了什么、有什么风险和需要我决定的事项。”
- “这个任务是否该交接？请生成 Handoff。”
- “请核对 Handoff 和实际项目状态后接管。”
- “检查当前文件是否过大、职责是否混杂，并提出拆分建议。”

## 不应触发或不应独立完成

- 单纯实现一个已经明确的小型代码修改。
- 替用户决定宠物形象、核心功能优先级或商业方向。
- 未经确认选择涉及隐私、持续付费、重要依赖或数据保存的方案。
- 自动创建一组角色型 Skill。
- 仅凭聊天或 Handoff 声称项目状态正确，而未核对项目事实。

## 核心工作流

### 1. 恢复项目上下文

- 读取项目规则、规划、发现、进度和相关 Handoff。
- 检查 Git 状态、当前分支/worktree 和任务相关代码或测试。
- 将文档陈述与可验证事实区分开；发现冲突时以实际代码和测试为准并记录差异。

### 2. 判断请求类型

将请求归为以下一种或多种：

- 新想法整理。
- 当前阶段规划。
- 范围或优先级调整。
- 状态与风险汇总。
- 代码职责和规模监督。
- Handoff 生成。
- Handoff 接管验证。

### 3. 保留用户决策权

- 明确哪些内容已经确认，哪些仍是建议。
- 普通执行细节可在授权范围内推进。
- 产品方向、核心功能类别、隐私、持续成本、重要依赖、数据保存、发布和大规模重写必须提出给用户决定。
- 提问时给出必要背景、选项影响和推荐，但不把推荐写成既定决定。

### 4. 控制探索期范围

- 使用“当前正在做 / 下一步可能做 / 想法池”三个分组。
- 每一阶段明确目标、成功标准、非目标、风险和待确认事项。
- 优先形成一个可体验、可观察、可推翻的小验证，不同时承诺多个未经验证的大功能。

### 5. 更新持久化记录

- 把已确认共识写入项目文档。
- 把阶段、状态和决策写入规划与进度记录。
- 把可复用方法与单次任务现场分开：前者进入 Skill，后者进入 Handoff。
- 长内容优先落盘并提供文件链接。

### 6. 阶段收尾

输出并记录：

1. 已完成。
2. 验证结果。
3. 当前进行。
4. 风险与阻塞。
5. 推荐下一步。
6. 需要用户决定的事项。

随后根据触发条件判断是否生成 Handoff。

### 7. Handoff 与接管

- 生成 Handoff 时使用统一模板，覆盖目标、范围、Git 状态、决策、改动、验证、风险、未完成项和接管步骤。
- 接管时先只读核对项目规则、Git、代码和测试。
- 对 Handoff 内容标记“已验证 / 不一致 / 尚未验证”，完成核对后才继续修改。

## 代码监督规则

- 文件达到约 400 行时检查是否承担多个职责。
- 500–600 行作为警戒范围，不作为机械限制。
- 超过 600 行时优先按职责评估拆分。
- 超过 1000 行必须说明原因并获得用户确认。
- 入口文件只负责启动、装配和依赖连接。
- 不创建万能 `Utils`，也不为了缩短文件而机械拆分。

## 第一版所需资源

### `SKILL.md`

保留触发描述、决策边界、核心工作流、资源路由和输出要求，控制篇幅。

### `references/project-rules.md`

保存 MochiDock 的角色、范围、阶段管理、代码规模和输出体验规则。

### `assets/handoff-template.md`

作为生成 Handoff 时复制并填写的统一模板，不作为知识文档加载。

### `agents/openai.yaml`

提供 Skill 列表展示名称、简短说明和默认提示词。

### 暂不需要脚本

第一版主要是判断与流程约束，没有稳定、重复且容易出错的机械操作；待实际使用暴露重复操作后再决定是否添加脚本。

## 第一版验收标准

- 能从典型触发语句正确进入 MochiDock 项目管理流程。
- 能区分事实、建议和待用户决定事项。
- 能阻止新想法无意扩大当前阶段。
- 能形成包含成功标准和非目标的小阶段计划。
- 能生成完整 Handoff，并在接管时执行只读核对。
- 能监督代码职责和规模，但不会机械拆分。
- Skill 目录通过官方快速校验。

## 创建前唯一待确认项

Skill 的保存位置：

- 推荐：项目内的 `.codex/skills/mochidock-pm/`，随 MochiDock 版本管理，项目规则与 Skill 同步演进。
- 备选：个人 Codex Skills 目录，跨项目可发现，但会让 MochiDock 专属规则与项目版本脱离。
