# MD-008 正式透明母帧稳定制作方案

## 目的

把已确认的鼠标接近注意方向转化为可接入 MochiDock 的稳定透明素材，同时避免重复出现整图漂移、透明边缘闪烁或尾巴断开的情况。

本方案只定义素材生产与验证边界，不授权产品代码开发。

## 已锁定的视觉意图

- 角色保持 v0.4 趴姿身份、比例、毛色、面纹和整体占位。
- 注意反馈采用轻微抬头与耳朵注意，表情平静，不张嘴、不兴奋。
- 尾巴从臀部自然连续伸出，只让外段形成一次中等幅度上扬。
- 尾巴不能悬空、断开、出现细桥、缺口或不自然折角。
- 动作只播放一次，视觉上不暗示持续摇尾。

## 正式母帧

制作两张新的 1254×1254 RGBA 母帧：

1. `attention-base`：注意基础帧。尾巴保持原待机姿态，头部与耳朵表达注意。
2. `attention-tail`：尾巴强调帧。头部、表情与身体保持 `attention-base`，只改变获准的尾巴外段。

正式母帧必须使用新版本文件名，不覆盖概念候选、原待机母版或 MD-005 素材。

## 输入与来源规则

- 原 v0.4 透明待机母版是唯一固定像素基底。
- 当前 attention v1–v4 棋盘格图片只作为姿态参考，禁止直接去背、缩放或作为正式母帧输入。
- 如果使用生成式工具产生局部来源，必须生成独立候选并保留原始文件；不得直接覆盖正式目录。
- 小熊猫毛发与尾巴边缘属于复杂透明对象。若需要模型原生透明输出，必须在执行前由用户确认相应工具路径；不得把烘焙棋盘格伪装为透明素材。
- 优先采用局部合成：固定待机基底，只引入头部/耳朵或尾巴许可区域内的必要变化。

## 版本化许可区域

许可区域采用追加版本、保留历史的方式演进：v1 是首次锁定版；v2 扩展 `tailMotion` 以覆盖完整旧尾巴；v3 新增 `bodyReconstruction` 并收窄 `tailRootAnchor`，用于重建原尾巴遮挡的后背与后腿。用户于 2026-07-20 验收的正式母帧使用 `md008-attention-masks-v3.json`；v1、v2 均保留为审计记录，不得静默覆盖。

正式处理前创建独立 JSON 蒙版定义，并通过可视化叠加图让用户确认。至少包含：

- `attentionHead`：覆盖眼睛、眉部、耳朵及轻微头部注意变化，不覆盖前爪、身体或尾巴。
- `tailMotion`：覆盖原尾巴外段与新尾巴外段的联合包围区域，为清除旧轮廓和写入新轮廓预留空间。
- `tailRootAnchor`：覆盖臀部至尾根连接段；该区域是硬锚点，在 `attention-base` 与 `attention-tail` 之间不得发生位移或断开。
- `bodyReconstruction`（v3）：只覆盖原待机尾巴曾遮挡、清除旧尾巴后必须补齐的后背与后腿局部。

许可区域使用圆角或贴合轮廓的局部蒙版并允许有限羽化，但羽化结果必须裁回版本化许可范围。

## 像素与 Alpha 稳定契约

### 注意基础帧

- `attentionHead` 外的 RGBA 必须逐像素等同原待机母版。
- `attentionHead` 外的完整 Alpha 必须逐像素等同原待机母版。
- 尾巴、身体、前后爪和底部轮廓不得改变。

### 尾巴强调帧

- `tailMotion` 外的 RGBA 必须逐像素等同 `attention-base`。
- `tailMotion` 外的 Alpha 必须逐像素等同 `attention-base`。
- 允许 `tailMotion` 内 Alpha 改变，因为真实尾巴移动会露出旧背景并占据新位置。
- `tailRootAnchor` 必须与 `attention-base` 保持稳定连接；不得出现透明裂缝、悬浮尾巴或异常细桥。
- 头部、耳朵、面部、身体和四肢必须在两张注意帧之间完全稳定。

与 MD-005 不同，本任务不能强制整张 Alpha 与待机相同；稳定边界改为“许可区域内允许必要轮廓变化，许可区域外严格不变”。

## 尾巴连续性验证

除了静态目视，建立自动诊断：

- `tailRootAnchor` 内不得出现新增透明贯穿带。
- 尾根关键截面的有效 Alpha 覆盖不得低于预设阈值。
- 从臀部锚点到尾巴主体应属于连续有效 Alpha 区域，不得形成独立悬浮组件。
- 输出尾根局部放大对比图，分别叠加在浅色、深色和代码文字背景上检查。
- 120 px 缩略图必须单独检查，避免高分辨率下不明显的断裂在桌面尺寸中被放大。

## 尺寸生产

- 正式母帧确认后再确定性生成 80、120、160、240、320 五档产品素材。
- 每档以对应尺寸的既有待机或注意基础素材作为固定基底，重新应用缩放后的版本化许可区域。
- 不直接对最终整张动作图进行无约束缩放，避免重采样把差异扩散到许可区域外。
- 正式尺寸源与 Asset Catalog 副本必须逐对 SHA-256 一致。

## 预览与人工评审

正式接入前至少提供：

- 1254 px 两张透明母帧。
- 120、240、320 三档静态对比。
- `待机 → attention-tail → attention-base → 待机` 的低速评审 GIF。
- 接近真实节奏的正常速度预览。
- 浅色、深色和代码文字背景上的尾根与透明边缘检查图。

用户需要确认：

- 注意感清楚但不兴奋。
- 尾巴连接自然，幅度不过强。
- 小尺寸下动作可辨认。
- 切换时没有整图漂移或透明边缘闪烁。

## 自动测试要求

新增确定性素材测试，至少覆盖：

1. 两张母帧画布、RGBA 模式和透明角落正确。
2. `attention-base` 只在 `attentionHead` 内变化。
3. `attention-tail` 只在 `tailMotion` 内变化。
4. 两张注意帧的 `tailRootAnchor` 连续性满足阈值。
5. 五档素材的许可区域外像素稳定。
6. Catalog 副本与正式尺寸源哈希一致。
7. 处理脚本重复运行结果一致。

测试需要先对当前缺失素材或不稳定候选产生真实 RED，再在稳定制作后进入 GREEN。

## 停止条件

出现以下任一情况时停止正式化并回到素材修订：

- 尾根断开或只能用背景、阴影掩盖连接问题。
- 为了尾巴动作必须改变大面积身体、脸型或角色比例。
- 许可区域外无法保持像素稳定。
- 120 px 下尾巴动作不可辨认，或幅度只能扩大到明显兴奋。
- 透明边缘处理需要改变已确认的角色毛色或产生明显色边。

## 执行顺序

1. 确认本方案。
2. 建立并预览版本化蒙版。
3. 产出两张独立透明局部来源候选。
4. 以原待机母版为基底进行稳定合成。
5. 运行母帧像素与尾根连续性测试。
6. 生成代表尺寸预览和动作 GIF，由用户验收。
7. 用户确认后生成五档正式素材与 Catalog 副本。
8. 素材验收完成后，MD-008 才进入可安排的产品开发阶段。
