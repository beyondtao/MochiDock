# MD-001：阶段 1A 最小桌面宠物

## 任务信息

- 状态：已完成
- 任务类型：产品开发与体验验证
- 产品负责人：用户
- 项目管理与验收：高级项目经理 Agent
- 开发执行：Codex 开发部门
- 创建日期：2026-07-18

## 任务目标

将当前 macOS Xcode 模板改造成第一个可实际体验的 MochiDock：桌面上显示一个临时宠物形象，用户可以拖动它、点击获得明确反馈，并能通过清晰入口恢复显示或退出应用。

本任务的重点是验证桌面宠物的最小交互闭环，而不是完成正式视觉效果。

## 背景与用户价值

MochiDock 当前只有 Xcode 初始模板，尚无可体验的桌面宠物。完成本任务后，用户可以首次在真实工作环境中判断：宠物是否稳定、是否自然、是否干扰工作，以及是否愿意让它持续停留在桌面。

## 开发范围

1. 应用启动后只显示一个宠物窗口，不显示普通文档窗口。
2. 宠物窗口透明、无标题栏，内容区域约为 128×128，可根据实际渲染需要小幅调整。
3. 用户可以通过拖动宠物移动整个窗口。
4. 单击宠物产生立即可见的反馈；最低要求是在“休息”和“开心”两种表情间切换。
5. 提供常驻菜单栏入口，至少包含：
   - `Show Pet`：宠物被隐藏或关闭后重新显示同一个宠物窗口。
   - `Quit MochiDock`：明确退出应用。
6. 重复执行 `Show Pet` 不得产生多个宠物窗口。
7. 使用 SwiftUI 或系统绘图能力制作临时占位形象，不等待正式美术素材。
8. 移除不再使用的 SwiftData 列表、时间戳模型和空模板测试代码。

## 明确非目标

- 不制作或选择正式宠物视觉形象。
- 不实现复杂动画、自动移动、鼠标追踪或多种行为状态。
- 不保存窗口位置、宠物状态或用户设置。
- 不实现设置页面、开机启动或发布流程。
- 不加入工具功能、AI、聊天、知识库或网络请求。
- 不引入第三方依赖。
- 不擅自让窗口跨所有 Space 或覆盖全屏应用；这类行为等待实际体验后决定。

## 验收标准

### 自动验证

- [x] 项目可在当前 Xcode 26.4.1、macOS 26.4 deployment target 下完成 Debug 构建。
- [x] 测试覆盖宠物点击状态从休息切换到开心、再次点击恢复休息。
- [x] 测试或等价的可复现验证证明重复显示操作复用同一个宠物窗口。
- [x] 全部新增及现有有效测试通过。

### 人工体验验证

- [x] 启动后只出现一个无普通标题栏、无不透明背景的宠物。
- [ ] 宠物可拖动到不同屏幕位置，松开后保持在新位置。
- [ ] 连续点击两次能够清楚观察到两个状态之间的切换。
- [ ] 切换到其他普通应用后，宠物行为稳定且不会阻止宠物范围外的正常操作。
- [ ] `Show Pet` 可以恢复宠物，重复使用不会增加窗口数量。（MD-003 已补齐动态 Hide/Show 路径，等待用户在最终构建中确认。）
- [ ] `Quit MochiDock` 可以正常结束应用。
- [x] 连续显示 30 分钟期间没有窗口增殖、意外消失或交互失效。

人工体验部分由用户或高级项目经理在开发部门提交后执行；Codex 应先完成可由开发环境验证的部分。

## 技术与项目约束

- 使用现有 Swift、SwiftUI 和 AppKit 能力，保持 macOS 原生实现。
- 应用入口只负责启动、对象装配和菜单连接；窗口管理、互动状态和宠物视图应具有清晰职责边界。
- 不要创建万能工具类，也不要为了文件数量机械拆分。
- 新增文件应保持可在有限上下文中完整理解；若单文件接近 400 行，先检查是否混合职责。
- 不改变产品方向、部署目标、Bundle Identifier 或签名设置，除非构建确实受阻并先向用户说明。
- 不提交与本任务无关的格式化、重构或功能修改。
- 保留工作区中已有的项目文档改动，不覆盖或撤销用户及其他 Agent 的修改。

开发部门可以自行选择具体窗口封装和测试方式。已有的[阶段 1A 技术实施参考](../../superpowers/plans/2026-07-18-stage-1a-minimum-desktop-pet.md)可供参考，但它不是不可调整的技术命令；如采用不同方案，必须仍满足本任务的范围和验收标准。
