# MD-012：阶段 2 稳定试用与体验收口

## 任务信息

- 状态：已完成
- 任务类型：阶段 2 体验验证与收口
- 产品负责人和最终验收：用户
- 统筹、问题分流与独立复核：高级项目经理 Agent
- 开发执行：Codex 开发部门，仅处理经确认的可复现缺陷
- 前置依赖：MD-010 与 MD-011 完成人工验收和归档

## 任务目标

使用固定版本进行 5～7 天真实桌面试用，判断 MochiDock 是否已经达到“愿意长期留在桌面”的阶段目标，并以真实体验选出后续唯一优先问题，而不是继续凭想象增加功能。

## 最小可验证体验

1. 先完成 MD-010 与 MD-011 的人工验收，固定一版试用基线。
2. 连续 5～7 天按日常方式使用，不主动寻找边界问题，也不在期间加入新功能。
3. 只记录四类事实：打扰点、消失/恢复/启动异常、最喜欢的互动、最希望改善的一件事。
4. 每个问题记录出现条件、频率、是否可复现，以及是否影响继续使用。
5. 试用结束后由高级项目经理汇总，用户决定阶段 2 是否收口，以及下一步进入宠物个性、小型工具场景，或继续保持当前版本。

## 范围

- 固定版本的真实桌面试用与少量事实记录。
- 对阻塞性或高频可复现缺陷进行独立复核和优先级判断。
- 只有用户确认需要修复时，才形成明确修订范围交给开发团队。
- 试用结束时产出阶段 2 收口报告和一个推荐的后续方向。

## 明确非目标

- 不建立遥测、埋点、账户、反馈后台或自动上传。
- 不在试用期间新增动作、设置、素材、依赖、权限、网络或 AI。
- 不邀请外部测试者，不进入分发、签名公证、自动更新或公开发布。
- 不预先承诺屏幕边缘偷看、睡眠、成长系统或工具能力。
- 不进行无真实问题驱动的重构或性能优化。

## 成功证据

- MD-010 与 MD-011 已由用户完成真实体验验收并归档。
- 固定版本完成 5～7 天实际使用，没有阻塞继续使用的稳定性问题；若出现问题，已有可复现记录和明确处置决定。
- 用户能够明确回答：是否愿意让 MochiDock 继续留在桌面，以及下一步最想改善的一件事。
- 高级项目经理完成阶段 2 收口总结，清楚区分已验证事实、推断、建议和仍需用户决定的事项。

## 问题分流规则

- **阻塞问题：** 崩溃、宠物无法恢复、设置或登录启动严重失效。暂停试用，先由高级项目经理复核，再由用户决定是否交开发团队修复。
- **高频摩擦：** 多次发生但不阻塞使用。继续记录到试用结束，统一决定优先级。
- **偶发边界：** 记录条件，不自动创建修复任务。
- **新想法：** 放入想法池，不并入 MD-012。

## 验收与停止条件

- 若 5～7 天内没有阻塞问题，并能形成一个明确的下一步判断，MD-012 可验收完成。
- 若出现阻塞问题，MD-012 暂停但不扩大；问题复核后由用户决定修复范围。
- 若试用结束仍没有明显新需求，可以直接收口阶段 2 并长期维持当前版本；“没有新任务”也是有效结果。

## 后续候选

当前推荐的第一候选仍是“屏幕边缘躲藏与偷看”的最小实验，用于验证宠物个性和记忆点；是否形成后续编号，必须等待 MD-012 的真实体验结论和用户确认。
