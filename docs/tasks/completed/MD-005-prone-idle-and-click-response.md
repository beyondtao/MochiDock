# MD-005：趴姿待机与点击回应接入

- 状态：已完成

- 产品负责人：用户

## 任务目标

在 `MD-004` 已完成趴姿与程序化呼吸的基础上，加入偶尔眨眼和单次点击开心回应，完成“有生命感但不打扰”的最小桌面宠物体验。

## 开发范围

- 保持 `MD-004` 已确认的趴姿、三档尺寸和程序化呼吸方式，不改回呼吸帧序列。
- 待机大部分时间停留在安静趴姿，沿用低频、带停顿的呼吸节奏。
- 偶尔播放一次短促眨眼，动作之间存在明显静止间隔。
- 点击回应采用已确认的“三张新母帧＋程序化弹起”方案：母帧承担必要的离散造型/表情变化，程序负责位移、缩放、节奏、回落与恢复待机，不制作完整逐帧弹跳序列。
- 三张新母帧固定为半闭眼趴姿、全闭眼趴姿、开心趴姿；眨眼按原待机、半闭眼、全闭眼、半闭眼、原待机往返，点击回应使用开心趴姿。
- 保留拖动、尺寸切换、Hide/Show 和 Quit 行为。

## 明确非目标

- 不做鼠标跟随或看向指针。
- 不做自动走动、飞行、睡觉、吃东西或多种随机反应。
- 不做设置页、开机启动、数据保存、换装、成长、工具或 AI。
- 不在本任务重新设计角色或生成额外动作包。
- 不引入第三方依赖。

## 验收标准

### 自动验证

- 默认视觉状态是趴姿待机，不是站立图。
- 待机动作不会无停顿地持续循环。
- 眨眼与点击回应结束后会返回同一趴姿待机状态，并继续由 `MD-004` 的程序化呼吸管理待机生命感。
- 点击回应期间的快速连续点击行为稳定。
- 尺寸切换、Hide/Show 和重复显示不会创建新面板或丢失播放能力。
- 全部既有有效测试继续通过。

### 人工体验验收

- 启动后小熊猫以趴姿显示，三档尺寸都没有裁切或不透明底色。
- 呼吸/起伏幅度轻微，眨眼自然，动作之间有足够停顿。
- 点击回应可辨识，约一次短促动作后恢复待机，不持续兴奋或晃动。
- 拖动与点击仍能正确区分。
- 连续放置在桌面 30 分钟，用户能感觉角色是活的，但不会被频繁吸引注意。
- 运行期间没有窗口增殖、意外消失、动画卡死或明显异常资源占用。

## 风险与阻塞

- 眨眼与点击回应的生成帧仍可能出现头身比、面纹、尾巴或毛色漂移，素材必须先作一致性评审；呼吸不再使用生成帧。
- 趴姿的占地比例与现有站姿不同，可能需要调整图像内边距，但不应在未确认前改变三档面板尺寸定义。
- 如果素材无法在帧序列中保持角色一致，先停止接入并回到素材修订，不用代码掩盖视觉漂移。

## 验收调整：点击切图闪烁

- 用户在实际点击验收中观察到切换开心帧时出现闪烁，因此首轮交付不通过验收，任务退回“开发中”。
- 只读像素诊断确认窗口和面板没有重建或改变背景色；点击瞬间同时切换整张图片、增加亮度并开始几何压缩。
- 120 px 待机帧与开心帧画布和 Alpha 包围盒相同，但有 809 个像素的 Alpha 值不同；共同完全不透明区域内 3330 个像素的 RGB 发生变化。差异分布在面部、耳朵、身体和底部边缘，不只在表情区域。
- 根因是动作帧经过独立生成和独立绿幕去除，导致本应保持静止的角色主体与抗锯齿 Alpha 边缘也随资源切换变化；透明窗口放大了这种全局帧差。`.brightness(0.025)` 是额外放大因素，但不是唯一根因。
- 建议修正方向：以已确认的原待机透明图作为固定像素基底，只合成动作帧必要的眼睛/嘴部区域，确保非表情区域与 Alpha 轮廓逐像素保持一致；再确定性生成五档素材并替换 Asset Catalog 副本。不得仅用代码淡入淡出掩盖素材漂移。

## 第二轮验收缺陷：资源替换与尺寸重绘透底（2026-07-20）

- 用户真实桌面复验确认：点击切换与眨眼时仍能短暂看到宠物后方的代码文字；切换显示尺寸时也有相同的透底现象。边缘本身已感觉稳定。
- 用户目前无法可靠判断落下恢复阶段是否发生第二次闪烁，因此该项保持未确认，不推断为通过或失败。
- 第一轮稳定素材修正确认有效地消除了 Alpha 外轮廓与非表情像素漂移，但没有消除运行时资源替换或透明窗口重绘造成的短暂透底；本任务不通过本轮人工验收，状态退回“开发中”。
- 代码复核发现高可信风险点：`visualState` 与 `animationState` 在同一次更新中变化，而 `.animation(..., value: model.animationState)` 位于整条 `Image` 修饰链上，可能把图片资源替换包含进隐式动画事务并产生内容淡化。
- 尺寸切换路径先更新 `model.displaySize`，随后才同步调整透明 `NSPanel` frame；图片资源、SwiftUI frame 与透明面板缓冲区重绘缺少明确的原子更新边界，可能产生短暂空帧或半透明帧。
- 上述两项是基于代码和现象形成的待开发验证假设，尚不能仅凭静态检查宣称为最终根因。下一轮必须先用最小诊断或回归测试证明触发机制，再实施修正。
- 修正范围仅限：让离散图片资源切换不参与淡入淡出；只对 `scaleEffect` 与 `offset` 保留明确动画；让尺寸资源与面板尺寸以无动画、无空帧的方式一致更新。不得用不透明底色、遮罩背景或延长淡入淡出来掩盖问题。
- 素材像素稳定约束、眨眼顺序与频率、点击节奏、五档尺寸定义、面板数量、菜单、偏好、本地化和依赖均保持不变。
