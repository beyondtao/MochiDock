# MD-007：英文与简体中文本地化基础

## 背景与用户价值

当前应用的菜单、尺寸名称和无障碍文案直接写为英文，项目尚无本地化资源。现阶段用户可见文案数量很少，是用较低成本建立统一本地化边界的合适时机；后续新增设置和互动文案时可直接沿用，避免继续积累硬编码字符串。

首轮只覆盖英文与简体中文，并跟随 macOS 系统语言，不在应用内增加独立语言设置。

## 已确认产品决策

- 英文作为开发语言和回退语言。
- 首批新增简体中文。
- 使用 Apple 原生本地化能力与 Xcode String Catalog。
- 应用语言跟随 macOS 系统和应用语言设置。
- `MochiDock` 作为品牌名不翻译。
- 德语、繁体中文、日语及其他语言暂不进入承诺范围。

## 开发范围

- 建立项目的 String Catalog 本地化基础。
- 本地化状态栏菜单中的宠物显示/隐藏、尺寸选择和退出文案。
- 本地化五档尺寸的展示名称，同时保留 80、120、160、240、320 数值。
- 本地化宠物的无障碍标签和状态值。
- 保证动态 `Show Pet` / `Hide Pet` 文案在英文和简体中文下均与实际面板状态一致。
- 保证未命中翻译时安全回退到英文。

## 明确非目标

- 不增加应用内语言切换器或语言偏好持久化。
- 不翻译 `MochiDock` 品牌名。
- 不修改 `pet.displaySize`、`PetDisplaySize.rawValue`、资源名称或其他稳定程序标识。
- 不本地化开发专用 Preview 名称、测试名称、日志或代码注释。
- 不加入德语、繁体中文、日语或其他语言。
- 不引入第三方本地化框架或远程翻译服务。
- 不修改动画、面板行为、尺寸持久化或开始 `MD-005` 动作素材接入。

## 验收标准

### 自动验证

- 项目包含英文与简体中文 String Catalog，构建可识别两种本地化。
- 所有当前面向用户的菜单与无障碍文案均通过本地化资源提供，不再依赖散落的硬编码展示文本。
- 五档尺寸在两种语言下均保留正确点数，并继续映射到原有稳定 raw value。
- 切换语言不影响已保存尺寸恢复、菜单选中状态、Show/Hide、动画或资源映射。
- 全部既有测试继续通过。

### 人工验收

- 在英文环境下，菜单、五档尺寸和无障碍文案显示自然且无回归。
- 在简体中文环境下，菜单完整显示中文，无截断、混杂英文或歧义。
- 两种语言下动态显示/隐藏菜单标题与宠物实际可见状态一致。
- 两种语言间切换后，之前保存的尺寸仍正确恢复并保持勾选。

## 技术与项目约束

- 优先使用 SwiftUI 和 Foundation 可直接识别的本地化字符串类型，不建立自定义全局字符串工具容器。
- 展示文本与持久化值必须保持分离；翻译变化不得造成偏好迁移。
- 如果实施要求修改稳定 raw value、偏好键、资源名、Bundle Identifier、deployment target 或加入第三方依赖，停止扩展并向用户报告。
