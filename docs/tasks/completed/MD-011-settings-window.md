## 目标与验收范围

- 状态栏菜单只保留动态“隐藏/显示宠物”、“设置…”和“退出 MochiDock”。
- “设置…”打开单一且可重复唤起的独立窗口。
- 设置窗口仅包含宠物尺寸、鼠标接近回应、登录时启动，复用现有持久化和系统真实状态。
- 关闭设置窗口不退出应用、不隐藏宠物，也不产生多个窗口。
- 英文与简体中文完整；不新增其他设置、依赖、权限或通用设置框架。
- 保留并验证 MD-010 全部行为。

## 已确认的双栏视觉与尺寸交互修订（2026-07-22）

- 设置窗口采用左侧栏目、右侧内容的双栏结构；当前栏目仅为“宠物”和“应用”，不预先展示空栏目。
- 左侧保留克制的宠物氛围与现有角色素材；宠物感不改变原生 macOS 控件的可理解性。
- “宠物尺寸”不再使用五段式按钮，改为一条较细的水平离散滑块。
- 滑轨对应现有 `80 / 120 / 160 / 240 / 320` 五档，在五个固定位置显示小圆点；不产生连续尺寸或第六种尺寸。
- 用户拖动滑块时，滑块必须吸附到最近的圆点；直接点击某个圆点也应选择对应档位。
- 键盘左右方向键应能逐档切换；控件需要保留可理解的当前档位和值说明，不能只依靠圆点位置表达。
- 每次档位确定后继续调用现有尺寸选择、窗口更新和持久化路径，不新增偏好键或第二套尺寸状态。
- 这轮修订只改变设置窗口布局与尺寸选择控件，不增加新的设置项。

## 第二轮人工验收退回（2026-07-22）

- **用户实测阻塞：** 圆点可以点击，但从当前圆点开始拖动不能改变档位，不满足已确认的核心拖动体验。
- **用户实测视觉问题：** 滑块获得键盘焦点后，系统蓝色焦点环包围整个滑块矩形；窗口失去激活后该矩形消失，证明它是容器焦点视觉而非尺寸选中状态。当前表现过重，需要收敛。
- **已验证根因：** `DragGesture` 只挂在底层轨道 `Capsule`，五个覆盖其上的圆点是独立 `Button`；从圆点开始的指针事件由按钮接收，不能可靠进入底层拖动手势。
- **已验证测试缺口：** 当前所谓拖动测试只验证 `nearestSize(to:)` 的纯数值映射，没有驱动 SwiftUI 视图的真实指针手势，因此不能证明 UI 可以拖动。
- **已验证焦点来源：** 整个滑块根容器使用 `.focusable()` 和默认焦点效果，导致系统为整块 `VStack` 绘制蓝色矩形焦点环。
- **修订要求：** 用户从当前圆点、任意圆点或轨道任意位置按下并拖动时，都必须连续命中统一的拖动区域并按最近档位吸附；圆点点击与键盘逐档操作继续保留。
- **焦点要求：** 保留键盘可访问性，但不得再显示包围整块滑块的蓝色矩形；如需焦点提示，应限制为当前圆点或轨道附近的克制视觉，且不能与“当前尺寸”状态混淆。
- MD-011 从“待验收”退回“开发中”；修正后必须进行真实鼠标拖动人工验证，纯模型测试不能再次作为拖动完成证据。

## 多桌面空间行为确认（2026-07-22）

- **用户决定：** 设置窗口关闭后若用户切换到另一个 macOS 桌面空间，再次点击“设置…”时，同一个设置窗口应移动到当前活动桌面并在此处前置，不得把用户切回窗口上次所在的桌面。
- 设置窗口仍只创建并复用一个 `NSWindow`；不得通过为每个桌面创建窗口实现。
- 该行为只适用于设置窗口。宠物面板继续沿用现有跨全部桌面显示策略，不得修改其 `canJoinAllSpaces` 行为。
- 不要求设置窗口同时显示在所有桌面；不得为设置窗口使用 `canJoinAllSpaces`。
- 自动测试至少检查设置窗口采用“移动到当前活动桌面”策略、没有采用“加入所有桌面”策略，并继续满足单窗口复用。
- 人工验收路径：桌面 2 打开并关闭设置 → 切换桌面 1 → 再次打开设置；结果应停留在桌面 1 并显示设置窗口。
