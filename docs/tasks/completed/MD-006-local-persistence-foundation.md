# MD-006：本地偏好持久化基础

- 状态：已完成
- 任务类型：阶段 1 本地数据基础

## 背景与用户价值

当前尺寸每次启动都回到默认 120，用户需要重复选择。未来还可能出现成长值、等级、已拥有服饰、当前穿戴与互动统计等数据，因此需要在第一个真实保存需求上建立清晰、可测试、可扩展的本地持久化边界。

## 已确认架构决策

- UserDefaults 保存显示尺寸、音效、动画偏好等小型设置。
- SwiftData 保存未来成长、服饰、解锁状态、穿戴关系与互动统计等领域数据。
- 图片与动画帧不存入数据库；继续使用 Asset Catalog 或后续资源包，数据库只保存稳定资源标识。
- 首轮不为尚未确认的成长或服饰字段提前创建空 SwiftData 模型；在第一个真实领域模型确认时再建立版本化 Schema 与迁移计划。

## 开发范围

- 在本地保存用户选择的 `PetDisplaySize`。
- 应用启动时恢复上次有效尺寸，首次启动仍为 120。
- 保存稳定的尺寸原始值，不保存菜单文案或 point 数值。
- 已保存值无法解析时安全回退到 120，并且应用仍可正常启动。
- 使用可注入的偏好存储边界或等价设计，避免测试污染真实用户 UserDefaults。
- 尺寸恢复与面板初始 frame 保持一致，不先以 120 创建面板后再可见跳变。

## 明确非目标

- 本任务不保存面板位置、显示/隐藏状态、mood 或动画进度。
- 不实现成长、经验、等级、服饰、解锁、穿戴或互动统计。
- 不创建没有真实业务字段的 SwiftData 实体或空容器。
- 不接入 CloudKit、iCloud、多设备同步、备份或多存档。
- 不修改 `MD-004` 动画参数，不开始 `MD-005` 动作素材接入。
- 不引入第三方依赖。

## 验收标准

### 自动验证

- 无已保存值时默认为 120。
- 五档尺寸均可保存并在新模型实例中恢复。
- 无效或旧值会回退到 120，不崩溃。
- 选择尺寸后立即写入偏好存储。
- 测试使用隔离存储，不依赖开发机已有偏好。
- 恢复后面板尺寸与菜单选中状态一致。
- 现有动画、点击、面板、Hide/Show 和资源测试继续通过。

### 人工验收

- 切换到任意非默认尺寸，退出 MochiDock 并重新启动后，尺寸和菜单选中状态均恢复。
- 首次启动或偏好被删除后仍为 120。
- 启动时面板没有从 120 瞬间跳到已保存尺寸的可见闪动。

## 风险与停止条件

- UserDefaults 键名和尺寸原始值一旦发布即构成迁移契约，需集中定义并避免随意改名。
- 如果实施要求创建 SwiftData 领域模型、保存额外状态或接入云同步，停止扩展并由用户确认新范围。
