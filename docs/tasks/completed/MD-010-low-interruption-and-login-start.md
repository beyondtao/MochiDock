# MD-010：低打扰控制与登录时启动

## 任务信息

- 状态：已完成
- 任务类型：阶段 2 日常控制与启动可达性
- 产品负责人：用户
- 项目管理与验收：高级项目经理 Agent
- 开发执行：Codex 开发部门
- 前置依赖：MD-006 本地偏好基础、MD-008 有限鼠标接近回应，以及 MD-009 位置恢复均已完成

## 任务目标

让用户可以从菜单关闭鼠标接近回应并保存选择，同时可以控制 MochiDock 是否随 macOS 登录自动启动。完成并验收后，不继续堆叠新功能，先进入稳定试用与阶段收口观察。

## 背景与用户价值

当前版本已经适合日常放在桌面，但有限鼠标接近回应始终启用，且每次登录仍需手动启动应用。用户于 2026-07-21 明确确认把这两个日常摩擦纳入 MD-010，并选择在任务完成后长期使用当前版本，再根据真实体验决定后续功能。

## 用户可体验的最小闭环

1. 菜单提供清晰的“鼠标接近回应”开关，默认保持当前开启行为。
2. 关闭后立即停止鼠标接近检测和对应注意动作；点击、拖动、呼吸、眨眼、Hide/Show 继续工作。
3. 退出并重新启动应用后，接近回应开关保持用户上次选择。
4. 菜单提供清晰的“登录时启动”开关。
5. 开启或关闭后，菜单状态与 macOS 当前登录项状态一致；下次 macOS 登录时按选择自动启动或不启动 MochiDock。
6. 自动启动不得产生重复实例，也不得破坏尺寸、位置和低打扰偏好的恢复。

## 开发范围（已确认并已安排）

- 在现有菜单中增加鼠标接近回应开关，并保存为轻量本地偏好。
- 关闭时停止接近采样；如果接近注意动作正在播放，取消该动作并回到普通待机调度。重新开启后从干净的未武装状态恢复，避免立即误触发。
- 在现有菜单中增加登录时启动开关，优先使用 macOS 原生登录项能力。
- 菜单勾选状态必须反映实际状态；系统状态与应用预期不一致时，应安全同步或给出可理解的状态，而不是假装成功。
- 为英文和简体中文补齐新增菜单文字。

## 明确非目标

- 不关闭点击互动、呼吸、眨眼或所有自动动作；本轮只控制鼠标接近回应。
- 不建立设置窗口，不增加动作频率滑杆、免打扰时段或多组预设。
- 不实现后台守护进程、辅助功能、输入监控、全局事件监听或第三方启动器。
- 不进入公开发布、自动更新、安装器、签名公证或商店工作。
- 不增加新角色动作、成长系统、工具、AI、遥测或网络服务。

## 验收标准

### 自动验证

- 接近回应开关默认值与当前行为兼容，保存后可由新实例恢复。
- 关闭时不启动或会停止接近采样，不触发注意动作；开启后可正常重新触发。
- 点击、拖动、呼吸、眨眼、Hide/Show、尺寸与位置恢复不受影响。
- 登录时启动的启用、停用、状态读取和错误路径均通过可注入边界测试；重复操作保持幂等。
- 系统返回“需要用户批准”时不得显示为已启用；菜单应反映真实状态并给出可理解的处理结果。
- 新增菜单项的英文和简体中文键完整，现有本地化回归继续通过。
- 全部有效 `MochiDockTests`、既有素材稳定测试和无签名干净 Debug 构建继续通过。

### 人工验收

- 从菜单关闭接近回应，反复靠近和离开宠物，确认不再出现接近注意动作；点击与待机动作仍正常。
- 退出并重新启动，确认关闭状态保持；重新开启后接近回应恢复。
- 开启登录时启动，完成一次 macOS 注销/登录或等价的真实登录项检查，确认 MochiDock 自动启动且只有一个实例。
- 关闭登录时启动，再次检查登录后不自动启动；手动启动仍正常。
- 确认自动启动后正确恢复上次尺寸、位置和接近回应选择，没有明显闪跳或额外权限提示。

## 技术与项目约束

- 接近回应偏好复用现有轻量偏好边界，键名集中定义，测试不得污染用户真实偏好。
- 登录项优先使用 Apple 原生 API，不新增第三方依赖；开发部门需先核对当前 deployment target 与所选 API 的兼容性。
- Apple `SMAppService` 要求实际应用经过代码签名。无签名构建只作为编译和回归证据；真实登录项启停必须使用正常签名的 Xcode 运行版本或等价签名产物人工验证，本任务不因此修改既有签名配置。
- 保持单一 `NSPanel`、单一应用实例和现有动画调度边界。
- 不为了本任务进行无关重构。若修改文件接近 400 行，应检查职责；500–600 行进入警戒范围，超过 600 行优先按职责拆分。
- 开发采用测试先行；若真实登录流程无法完全自动验证，必须明确列入人工验收。

## 风险与停止条件

- macOS 登录项状态可能受系统设置或用户手动修改影响；菜单不能只显示应用内缓存值。
- 登录项可能处于未注册、已启用、需要用户批准或未找到等系统状态；实现必须显式处理，不能把注册调用成功等同于最终已启用。
- 自动启动的真实效果无法仅靠单元测试证明，必须保留至少一次系统级人工检查。
- 如果实施需要新的系统权限、后台辅助进程、受保护签名能力、重要工程配置变化或第三方依赖，停止扩展并请求用户决定。
